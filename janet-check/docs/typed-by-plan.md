# План: тип вызова, который вычисляет библиотека (`:typed-by`)

**Статус (2026-09-23):** шаги 1–3 сделаны, и вызовы после макросов тоже: обход идёт по
раскрытию (`macex1` шаг за шагом), вызов из исходника держит своё место, вызов, которым макрос
раскрывается целиком, получает место макроса, более глубокий — никакого. Отличия от плана: натива `db/query-shape` нет —
чекер запускает обычный `janet`, а не VM arc, поэтому правило `arc/query-type`
(`crates/arc/janet-zed.exports/arc/arc.janet`) разбирает `:find` само, на Janet. Ссылка
(`?e`) — `:abstract`, как её отдаёт хост. `:typed-by` в метаданных `defn` — символ (метаданные
не вычисляются) и разрешается в модуле, который определил функцию. `arc/pull-type` типизирует `db/pull`; `:db/id` — тоже `:abstract`.

Задача-повод: `db/q` в arc объявлен с `:ret :any`, и 173 вызова в platelab типизируются руками
(`{:type :boolean?}`), хотя тип следует из литерала запроса и литеральной схемы.

Это не задача про datalog. Тот же случай: PEG-грамматика, строка `string/format`, SQL, маршрут
веб-фреймворка, `spork/schema`, JSON-схема. Общее: **результат вызова следует из литерального
аргумента и из данных, объявленных где-то в программе.** Парсить каждый такой DSL в Rust внутри
janet-check значит учить чекер библиотекам по одной; datalog-план был первой из них.

Вместо этого правило поставляет библиотека, как функцию на Janet. Чекер уже умеет всё, что нужно:

- `check.janet` живёт долго, компилирует каждую форму файла, выполняет чистые `def` и загружает
  импортированные модули целиком: **значения схемы уже есть в его окружении**;
- отчёт проверки уже возвращает в Rust типы, записанные на Janet (`Binding.annotation` в
  `janet/mod.rs`), и Rust читает их обычным парсером аннотаций;
- `types.janet` уже пишет тип как данные обратно в синтаксис деклараций.

## 1. Объявление

Ключ метаданных `:typed-by`, рядом с `:params`/`:ret`, в `*.d.janet` или в настоящих метаданных
`defn`:

```janet
(defn db/q
  {:params [:any :any] :ret :any :typed-by arc/query-type :throws [ArcError]}
  "..." [query & inputs])
```

`arc/query-type` — обычная функция модуля библиотеки, который чекер может `require`
(syspath или `:libraries`):

```janet
(defn query-type [args env] ...)
```

- `args` — по одному элементу на аргумент вызова: `[:value v]` для статического аргумента, иначе
  `nil`. Статический — литерал, `'x`, `~x` без unquote, символ, чей `def` в окружении чистый
  (`check/pure?` уже решает это).
- Возвращает тип как данные в синтаксисе аннотаций (`:boolean?`, `'[:string]`, `{:a :number}`),
  или `nil`: тогда действует `:ret`.
- Что читать из `env`, решает функция: схема arc — это чистые `def` со структурами
  `{:db/valueType ...}`, их видно через `all-bindings`. Через `:include` вся программа загружена,
  так что схема видна и из файла, который её не импортирует.

## 2. Сторона Janet (`check.janet`)

- При обходе файла после `:expander` пройти **исходную** форму (не расширение): для каждого
  вызова, чей head — символ с `:typed-by` в окружении или среди `:declared`, и хотя бы один
  аргумент статический, вызвать функцию под `protect`.
- Записать `[line col annotation]` по `tuple/sourcemap` вызова; `annotation` — через
  `types/literal`.
- Ошибка или `nil` — записи нет, вызов остаётся с `:ret`. Молча: правило принадлежит библиотеке.
- Отчёт: `{:problems ... :bindings ... :provided {path [[line col annotation] ...]}}`.

`ponytail:` вызов, который породил макрос, не виден: обходится исходник. Добавить обход
`macex`, когда найдётся реальный пример.

## 3. Сторона Rust

- `Report.provided: HashMap<PathBuf, Vec<Provided {line, col, annotation}>>`, хранится в
  `Workspace` там же, где `bindings` из отчёта, с теми же правилами свежести: до прихода отчёта
  вызов типизирован по `:ret`.
- `Infer::call` (`types/infer/calls.rs`): если у head есть запись по его позиции, результат вызова —
  распарсенная аннотация вместо `apply`. `inspect` не меняется: аргументы по-прежнему держатся
  за `:params`.
- Такой тип **записанный**, не `Dynamic`: он следует из литералов и правила, за которое отвечает
  автор библиотеки. Значит, `{:type :boolean?}` на `def`, спорящий с ним, — находка в `--strict`
  через существующий `fit`; ничего нового в проверках не нужно.
- Парсер аннотаций принимает `:typed-by` (символ) и не жалуется на него в `*.d.janet`.

Инвалидация: `check.janet` уже перезагружает изменённый модуль и его импортёров, LSP заново
проверяет открытый файл. `ponytail:` другие открытые файлы с записями `:provided` держат старый
тип до своей следующей проверки; перепроверять их при изменении файла программы — когда это
начнёт мешать.

Стоимость: Rust-вывод только читает карту по позиции, 5 мс/kloc не трогаем. На стороне Janet —
один вызов функции на статический вызов на проверку. Кэш по `[функция значения]` — только по
профилю.

## 4. Первое правило: datalog, в arc, не здесь

- `janet-zed.exports/arc/arc.d.janet`: `:typed-by arc/query-type` у `db/q`, потом у `db/pull`.
- Разбор `:find` уже есть в `arc-db-core/src/query/plan.rs`; выставить его нативом
  (`db/query-shape`: форма `:find`, переменные, агрегаты), чтобы Janet-правило не парсило запрос
  заново.
- Соответствие `:db.type/* → тип` живёт в правиле, а не в конфиге janet-check: `ref`, `instant`,
  `uuid` — абстрактные типы хоста.
- Переменные из `:where [?e :attr ?v]`: `?v` — тип атрибута, `?e` — `ArcRef`; литерал на месте
  `?v` — ограничение; `?a` на месте атрибута — `:any`; противоречивые факты — `nil`;
  `or`/`or-join` — объединение; `not` не привязывает; правила `%` и `[(f ?a) ?b]` — `:any`.
- Тип результата по `:find`:

| `:find` | Тип |
|---|---|
| `?x .` | `T?` |
| `[?x ...]` | `[T]` |
| `[?x ?y]` | `(or [T U] :nil)` |
| `?x ?y` (relation) | `[[T U]]` |
| relation + `:keys [a b]` | `[{:a T :b U}]` |
| tuple + `:keys` | `(or {:a T :b U} :nil)` |
| `count`, `count-distinct`, `sum`, `avg` | `:number` |
| `min`, `max` | `T` |

- `db/pull` по литеральному паттерну: `:attr` → `T?`, many → `[T]?`, `{:ref [...]}` →
  вложенная структура, `:ns/_attr` → `[{...}]?`, `*` → `{:keyword :any}`.

`ponytail:` вычисляемые атрибуты (`micro-schema`) и `?k` из `:in`, пришедший не литералом, —
`:any`: правило видит значения, не типы аргументов.

## 5. Проверки

- **janet-check, `fixtures/`:** крошечная библиотека с `:typed-by` (например, `shout` с правилом
  «строковый литерал → `:string`, иначе nil»). Снапшоты: hover показывает вычисленный тип; в
  `--strict` находка на спорящем `{:type}`; нестатический аргумент, `nil`, ошибка правила и
  отсутствие функции — везде `:ret`.
- Корпусная тишина и `a_thousand_lines_are_inferred_in_milliseconds` без изменений.
- **arc:** юнит-тесты правила на Janet по каждой строке таблицы; тест, что ключи соответствия
  покрывают все `db.type` в `arc-db-core`, как существующий тест расхождения имён.
- **platelab:** убрать `{:type :boolean?}` в `src/nutrition/backfill.janet:52`, `just types
  --strict`.

## 6. Порядок

1. `:typed-by` в парсере аннотаций; обход и `:provided` в `check.janet`; `Report` и
   `Infer::call`. Фикстура и снапшоты.
2. `arc/query-type` для `db/q`, натив `db/query-shape`, тесты, platelab.
3. `db/pull` тем же путём.
4. По желанию: PEG и `string/format` как правила ядра, поставляемые самим `check.janet`.

Не включено: синглтон-типы символов и строк в языке типов и операторы над типами (типизация DSL
из одних типов в Rust). Правило видит значения, и это дешевле. К дорожной карте Elixir-style
(`Dynamic(T)`, `fit`, сужение) не относится: вычисленный тип — записанный, и он подчиняется
`fit` и `--strict` как есть.
